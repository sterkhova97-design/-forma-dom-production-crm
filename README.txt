FORMA DOM — ПРОИЗВОДСТВЕННАЯ CRM, тест v0.1

Что работает:
- главная страница = список всех изделий в работе;
- столбцы: изделие, картинка, дата готовности, № договора, характеристики, чертёж,
  статус производства, плановая дата готовности;
- статусы: Каркас / Паралонка / Пошив / Обивка / Готов к отгрузке / Отгружен;
- ручной ввод плановой даты;
- «Добавить заказ» → история КП → выбор нужных изделий;
- последовательное заполнение ТЗ «Сохранить данные и заполнить следующее»;
- ТЗ: ткань, габариты, чертёж, опоры, швы, декоративные элементы + фото,
  тип подушек + фото, жесткость, замер, врезка розеток/бра, царга + фото,
  механизм + фото, адрес доставки;
- окно характеристик;
- печать характеристик на A4;
- если одно изделие «Отгружен» — строка становится бледной;
- если все изделия договора «Отгружены» — договор целиком появляется в «Архив»;
- срок <= 5 дней — оранжевый;
- просроченный срок — красный оттенок;
- тестовые данные сохраняются в localStorage браузера.

ВАЖНО ПРО ИСТОРИЮ КП
Текущая версия калькулятора формирует payload с items, но Tilda-обвязка записывает в форму
только Configuration и Total. Для нормальной связи CRM с каждым отдельным изделием
нужно сохранять items как JSON.

В crm.js есть строка:
  const KP_API_URL = "";

Для реальной истории заменить её на URL API, которое возвращает массив:
[
  {
    "id": "КП-2026-081",
    "date": "2026-08-25",
    "client": "Проект",
    "manager": "Екатерина",
    "items": [
      {"id":"1","name":"Диван Nube","qty":1,"image":""}
    ]
  }
]

КУДА ЗАГРУЖАТЬ ТЕСТ
Самый простой вариант для вашего текущего проекта Cloudflare:
1. Создать отдельный статический проект/деплой, например forma-dom-production-crm.
2. Cloudflare → Workers & Pages → Create / New deployment → Upload assets.
3. Загрузить папку forma-dom-production-crm-demo целиком.
4. Открыть выданный адрес *.workers.dev.

ЧТО НУЖНО ДЛЯ ЖИВОЙ СВЯЗИ
1. При сохранении КП сохранять requestId + items JSON в серверное хранилище.
2. Сделать закрытый GET /api/kp для CRM.
3. В crm.js прописать URL этого GET.
4. Позже туда же перенести сохранение заказов/файлов из localStorage в серверную БД.

Тестовая версия специально отделяет интерфейс от API: подключение реальной истории
не потребует переделывать таблицу и формы.
